解决Windows 的 PowerShell Execution Policy限制脚本运行

发表于2026-10-08|更新于2026-10-09
|浏览量:

问题

原因

Windows 系统默认的 PowerShell 执行策略通常是 Restricted，它禁止运行任何 .ps1 脚本文件。当你执行 npm 时，系统尝试调用 npm.ps1，但被策略拦截，从而报错。

ExecutionPolicy 是 Windows PowerShell 的一项安全功能，用于控制 PowerShell 加载配置文件和运行脚本的条件。它并不是一个安全边界（不能防止恶意用户绕过），而是一道防止用户无意中运行不安全脚本的防线。

查看当前策略：

策略值 含义 适用场景
Restricted 默认策略。不允许运行任何脚本文件（.ps1），但允许运行单个命令。 最安全的设置，适合不需要运行脚本的普通用户。
AllSigned 只允许运行经过数字签名的脚本，包括本地创建的脚本。 企业环境，要求所有脚本必须由受信任的发布者签名。
RemoteSigned 本地创建的脚本可以运行；从网络下载的脚本必须经过数字签名。 最常用、最推荐的平衡选择。兼顾安全与便利，适合大多数开发者和普通用户。
Unrestricted 允许运行任何脚本，但运行从网络下载的未签名脚本时会提示确认。 需要运行大量不同来源脚本的测试环境，但风险较高。
Bypass 不阻止任何操作，也不显示警告或提示。 用于特定程序（如 CI/CD 管道、自动化工具）嵌入 PowerShell 时，完全绕过策略。风险最高。
Undefined 表示未设置执行策略。如果所有作用域都是 Undefined，则实际生效的是 Restricted。 用于移除某个作用域的策略设置，使其继承上一级作用域。
Default 仅用于 Set-ExecutionPolicy 命令，表示将策略恢复为默认值（通常是 Restricted）。 快速恢复默认设置。

解决方法

通过管理员 PowerShell 修改当前用户的执行策略来允许运行脚本。
