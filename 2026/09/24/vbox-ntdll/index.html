eNSP Code 40 与 VirtualBox -5607 研究

发表于2026-09-24|更新于2026-09-24
|浏览量:

案发

本机安装完 eNSP 后，拖一台 AR 路由器点启动，必报 code 40。所有表现都和”Hyper-V 没关干净”一模一样，但有一个怪处：clonevm、snapshot、registervm 全部成功，只有 startvm 必死。

为了排查，我写了个小工具 fuck_ensp hook eNSP 的日志，定位到错误发生在 eNSP 启动 VirtualBox 的阶段；再手动命令行启动，终于吐出了关键日志：

翻译成人话：VirtualBox 进程重生（Respawn）后的自我净化阶段，校验本机 ntdll.dll 的内存映射大小与 PE 头声明的 SizeOfImage，两者差了 0x5000（5 个内存页），超出写死的容差，进程自杀。

这发生在 VMM 初始化之前——VirtualBox 根本没走到申请 VT-x 的那一步。

元凶

VirtualBox ≤ 5.2（以及早期 7.0）带有一套”加固”（Hardening）机制：进程启动时先重生一个干净子进程，逐一校验地址空间里的每个模块映像是否被篡改。其中对 ntdll 的校验逻辑，我后来直接从 5.2.30 的 VBoxHeadless.exe 里逆了出来（二进制里就嵌着源文件路径：SUPHardenedVerifyProcess-win.cpp）：

问题出在 Windows 11 24H2 之后：系统对 ntdll 采用了带热补丁预留的映射方式，实际映射比 PE 头声明的 SizeOfImage 多出几页保留页。多出几页并不固定，随每个月累积更新换发的 ntdll 构建浮动——2026 年 9 月 9 日的 KB5124008 带来的 ntdll 10.0.26100.9444 恰好差 0x5000，越过了 5.2 的容差。这不是微软”破坏”了 VirtualBox，而是一个 2019 年后停止维护的写死假设，撞上了系统侧的正常演进。Oracle 在 7.1 中修掉了这个检查（官方工单 #22162），但 5.2 是 EOL 版本，永远等不到补丁。

这同时解释了开头的怪现象：VBoxManage clonevm / snapshot / registervm 都是 VBoxManage 自己做磁盘和配置操作，不拉起受加固保护的虚拟机进程；只有 startvm 会启动 VBoxHeadless.exe，触发自检。所以”一半命令能用”不是玄学。

反转

“新版 Windows 又能用了”是真的——玄学其实是微软更新带来的随机运气。

差值是否超容差，完全取决于当月累积更新发的是哪个 ntdll 构建：差 0x5000 的构建一上，startvm 就死；换发差得少的构建，又活。9 月 23 日的累积更新把 ntdll 换成 10.0.26100.9549 后，我实测 VBoxHeadless.exe --startvm 已经能越过 -5607——加固通过了，进程一路走到 VMM 初始化才死在另一个错误上。同一个差值，普通进程里量出来是 5 页，VBox 进程里就是能过：校验结果存在进程间差异，唯一可信的判定永远是实际跑一次 startvm。

另一个值得警惕的事实：这类”随更新复活”没有保障，下个累积更新随时可能再炸回来。

前人之路：垫片

随着对加固机制的了解，我发现了 ensp-vbox-shim 这个项目。

它的思路是：安装 7.2.8 版 VirtualBox（前文提到，Oracle 在 7.1 已修掉这个检查），然后在 eNSP 和 VirtualBox 之间塞一层**”垫片”**——对 eNSP 假装自己是 5.2，背地里把调用翻译给真正的 7.2.x 执行，从而绕开整个加固时代。

直接补二进制

除了”垫片”，还有什么办法？

前文提到，问题是”VBoxHeadless.exe 触发自检，导致进程自杀”。那直接 patch 掉 VBoxHeadless.exe 不就行了？

我把校验逻辑定位到后，写了个通用 patcher：解析 PE → 找格式串 %s: SizeOfImage (%#x) isn't close enough to the mapping size (%#x) 的 RVA → 扫描 RIP 相对寻址引用 → 回溯 test r32, 0xfffff000 → 找守卫跳转。这里踩了个小坑：编译器生成的是短跳 74 rel8，而不是我预期的长跳 0F 84 rel32，第一版 patcher 空手而归——上反汇编器（Capstone）扫出来才真相大白。

最终方案干净得只有两个字节：74 xx → EB xx（je → jmp，差值校验永久跳过）。工具对 5 个含该校验的二进制全部定位成功（VBoxHeadless / VirtualBox / VBoxSDL / VBoxNetDHCP / VBoxNetNAT），打补丁前自动备份为 .vbp-origin，一条 --restore 即可还原。唯一要注意的是：写 Program Files 需要管理员权限。

它是把双刃剑——跳过的是 VirtualBox 反篡改自检的一环，属于潜在的安全隐患，别在生产或共享机器上用。
